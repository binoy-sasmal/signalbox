Ran 58 rather than 56 because unittest's loader counts an unimportable
module as one synthetic failing test. Both are import errors from missing
third-party packages in this interpreter, not failures of the code:
  test_analyse_fixture: ModuleNotFoundError: No module named 'google.transit'
  test_probe_units: ModuleNotFoundError: No module named 'httpx'

The credential gate is stdlib-only by design, which is why its suite runs
here and in CI with no dependency install. The other two modules cover the
Stage 0 probe and need httpx and the GTFS-realtime bindings.

**CI is not affected and this is not a finding against it.**
`.github/workflows/secrets-check.yml` already runs the gate job on the
narrow `test_check*.py` pattern with nothing installed, and runs the broad
`test_*.py` pattern in a separate job that installs requirements.txt first.
The 58-with-2-errors line above is what a bare local interpreter reports,
not what any enforced check reports.

What it corrects is only how the commit message reads: 56 is the right
number for the suite that commit changed, and it is not the number someone
gets by running the pattern in that suite's own docstring. Recorded because
the whole point of F3 is that a number in the record should arrive with the
output that produced it, including when the output says something slightly
more complicated than the number did.
